# SKILLS.md

Comprehensive guide for developing, testing, deploying, and managing **SFO Hub** —
the JTC Private Office AI cross-sell/upsell advisor. SFO Hub mirrors its sister app
[TaxHub](../taxhub) in stack and ops.

---

## 1. Local Development

### Environment setup

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # fill in secrets (see §7)
```

`.env.example` ships `DATA_STORAGE=sqlite` for a zero-infra local run. Set the
`NEO4J_*` vars and `DATA_STORAGE=neo4j` to use the default graph backend (§5).

### Seed demo data

All data is synthetic — generated by `data/synth.py` (no real client data).

```bash
python -m data.synth --services-only          # only the service catalogue + cross-sell graph
python -m data.synth --count 80               # catalogue + 80 SFOs + a recommendation funnel
python -m data.synth --count 120 --seed 7     # reproducible book (fixed RNG seed)
python sfostore.py                            # init schema + print stats (no data)
```

### Run the server

```bash
python -m uvicorn web.app:app --host 0.0.0.0 --port 5021
PORT=5031 python -m uvicorn web.app:app --port 5031     # override port
SFOHUB_PUBLIC=1 python -m uvicorn web.app:app --port 5021   # disable login for demos
```

Health check:
```bash
curl http://localhost:5021/health   # {"status": "ok"}
```

Default login: `ADMIN_EMAIL` / `ADMIN_PASSWORD` from `.env`
(seeded by `init_db`; defaults `admin@jtcgroup.com` / `change-me`).

### Key URLs (local, port 5021)

| URL | What |
|-----|------|
| `/` | 3-pane workspace (client book · AI advisor · profile+recs). `?sfo=<id>` opens a family |
| `/chat` (POST) | SSE stream from the LangGraph advisor |
| `/recommend/{id}` (POST) | Re-run the hybrid engine for one SFO |
| `/panel/{id}` | Right-panel refresh (profile + recommendations) |
| `/dashboard` | Analytics: interest heatmap, upsell funnel, pipeline value |
| `/services`, `/service/{id}` | Service catalogue + detail (cross-sell partners) |
| `/help` | In-app guide |

## 2. Tests (pytest)

```bash
source .venv/bin/activate
pytest tests/ -q                          # all
pytest tests/test_storage.py -q           # cross-backend storage contract
```

`tests/test_storage.py` is **one suite parametrised over both backends**
(`sqlite`, `neo4j`) so `DATA_STORAGE` can't silently change behaviour. The Neo4j
parametrisation **skips automatically** if no Neo4j is reachable — to exercise it,
bring up local Neo4j (§5) first.

When you add a `Storage` method: add it to `storage/base.py`, implement in **both**
`sqlite_store.py` and `neo4j_store.py`, and add a contract assertion here.

## 3. The cross/upsell engine

The product's core. Pipeline in `engine/crosssell.py`:

1. **Rules** (`engine/rules.py`) — transparent catalogue fires on the profile
   (current services, asset mix, pain points, AUM, stage) → candidate set.
2. **Graph expansion** — walks `(:Service)-[:CROSS_SELLS_TO]->(:Service)` from each
   held service to surface bundle partners.
3. **AI re-rank** (optional) — LLM scores each candidate for *this* family and
   rewrites the rationale in a relationship-manager voice. No key → rule/graph
   scores stand.
4. **Persist** — one `RECOMMENDED` edge/row per service; the funnel + analytics
   read off it.

**Add a service:** edit `data/services.yaml` (and `cross_sells` edges), re-seed.
**Add a rule:** append to `RULES` in `engine/rules.py` (keep `service` keys in sync
with the catalogue). Every recommendation stays traceable via `source` + `rule_id`.

## 4. AI / LLM configuration

Provider switch via `LLM_PROVIDER` (`rag/llm.py`):

- **`xai`** (dev) — xAI Grok, OpenAI-compatible. Set `XAI_API_KEY`,
  `XAI_BASE_URL`, `GROK_MODEL`.
- **`azure`** (prod) — Azure AI Foundry, also OpenAI-compatible. Set
  `AZURE_AI_FOUNDRY_ENDPOINT`, `AZURE_AI_FOUNDRY_API_KEY`, `FOUNDRY_MODEL`.

With no key, `ai_available()` is false: the chat falls back to the rule-based
recommender and AI scoring is skipped — the demo never hard-fails.

The advisor is a LangGraph `create_react_agent` (`agents/orchestrator.py`,
persona in `SYSTEM`) routing to 5 specialist tools in `agents/tools.py`
(profile / needs / services / recommend / benchmark). The open SFO is carried via
a `contextvar` (`agents/context.py`).

## 5. Storage backends

Selected at runtime by `DATA_STORAGE` (`storage/__init__.py`); callers use
`import sfostore as store`.

### SQLite / Postgres (`DATA_STORAGE=sqlite`)

Zero-infra. `DB_URL=sqlite:///sfohub.db` (default) or a Postgres DSN. List/dict
fields are JSON-encoded into TEXT columns for portability.

### Neo4j graph (`DATA_STORAGE=neo4j`, default)

Graph shape:
```
(:SFO)-[:HOLDS_SERVICE]->(:Service)
(:SFO)-[:RECOMMENDED {kind,score,status,est_value_usd}]->(:Service)
(:SFO)-[:HAS_CONVERSATION]->(:Conversation)-[:HAS_MESSAGE]->(:Message)
(:Service)-[:CROSS_SELLS_TO {weight}]->(:Service)
```

Local dev Neo4j (user-owned, no sudo):
```bash
scripts/neo4j_local.sh setup     # pull image
scripts/neo4j_local.sh start     # http://localhost:7474, bolt://localhost:7687
scripts/neo4j_local.sh stop
```
Then set `DATA_STORAGE=neo4j` + `NEO4J_*` in `.env` and re-seed.

Notes: stable `uid` from a `(:Counter)` node (never Neo4j `id()`); version-tolerant
DDL (5.x `REQUIRE` → 4.x `ASSERT`) so the same code runs locally and on AuraDB.

## 6. Deployment

### Docker / Coolify (dev, port 5021)

```bash
docker compose up -d web                       # web app
docker compose run --rm seed --count 80        # seed demo data (profile: tools)
docker compose --profile neo4j up -d           # optional bundled Neo4j (else use AuraDB)
```
Compose carries `coolify.managed` / `coolify.port=5021` labels; front with
Cloudflare as TaxHub does.

### Microsoft Azure (production target)

Azure Container Apps + Azure AI Foundry + managed Neo4j AuraDB + Key Vault + ACR.
Full walkthrough in [`docs/architecture_readme.md` §7](docs/architecture_readme.md).
Summary:

```bash
RG=sfohub-rg; LOC=westeurope; ACR=sfohubacr; APP=sfohub
az group create -n $RG -l $LOC
az acr create -n $ACR -g $RG --sku Basic --admin-enabled true
az acr build -r $ACR -t sfohub:latest .
az containerapp env create -n sfohub-env -g $RG -l $LOC
az containerapp create -n $APP -g $RG --environment sfohub-env \
  --image $ACR.azurecr.io/sfohub:latest --target-port 5021 --ingress external \
  --secrets aura-pass=<PW> foundry-key=<KEY> app-secret=<RANDOM> \
  --env-vars DATA_STORAGE=neo4j LLM_PROVIDER=azure \
    NEO4J_URI=neo4j+s://<id>.databases.neo4j.io NEO4J_USER=<id> NEO4J_DATABASE=<id> \
    NEO4J_PASSWORD=secretref:aura-pass \
    AZURE_AI_FOUNDRY_ENDPOINT=<endpoint> FOUNDRY_MODEL=<deployment> \
    AZURE_AI_FOUNDRY_API_KEY=secretref:foundry-key APP_SECRET=secretref:app-secret \
    ADMIN_EMAIL=<email> ADMIN_PASSWORD=secretref:app-secret
```

AuraDB gotcha: on the *Free* tier the username **and** database name are the
instance id (not `neo4j`) — trust the downloaded credentials file.

## 7. Environment variables

| Variable | Required | Default | Purpose |
|----------|----------|---------|---------|
| `DATA_STORAGE` | yes | `neo4j` | `neo4j` or `sqlite` |
| `DB_URL` | sqlite | `sqlite:///sfohub.db` | SQLite/Postgres DSN |
| `NEO4J_URI` / `NEO4J_USER` / `NEO4J_PASSWORD` / `NEO4J_DATABASE` | neo4j | bolt://localhost:7687 / neo4j | Neo4j/AuraDB connection |
| `LLM_PROVIDER` | no | `xai` | `xai` (dev) or `azure` (prod) |
| `XAI_API_KEY` / `XAI_BASE_URL` / `GROK_MODEL` | no | — / x.ai / grok-4-1-fast-reasoning | xAI Grok |
| `AZURE_AI_FOUNDRY_ENDPOINT` / `AZURE_AI_FOUNDRY_API_KEY` / `FOUNDRY_MODEL` | azure | — | Azure AI Foundry |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | yes | admin@jtcgroup.com / change-me | Seeded admin login |
| `SFOHUB_PUBLIC` | no | `0` | `1` disables login (demo mode) |
| `APP_SECRET` | yes (prod) | — | Session signing secret |
| `PORT` | no | `5021` | Web app port |

## 8. Troubleshooting

- **App won't start, Neo4j errors** — either start local Neo4j (§5) or set
  `DATA_STORAGE=sqlite` for a zero-infra run.
- **Chat returns "AI unavailable"** — no LLM key; set `XAI_API_KEY` (or the Azure
  Foundry vars). The rule-based recommender still works without a key.
- **No recommendations for an SFO** — the client may already hold the natural next
  services, or the book wasn't seeded; run `python -m data.synth --count 80`.
- **Neo4j tests skipped** — expected when no Neo4j is reachable; bring one up (§5).
- **Port already in use** — TaxHub uses 5011, SFO Hub uses 5021; override with `PORT`.
