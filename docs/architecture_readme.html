FastFund Technical Architecture

One relationship-to-filing platform for family offices.

Runtime

Browser
  └── FastHTML / Starlette (`web.app:app`)
      ├── Identity, teams, roles and audit
      ├── Tax & Compliance
      ├── Knowledge & regulatory change
      └── `/family` relationship and outreach domain

All routes share the same process, environment, DB_URL and APP_SECRET.

Connected domain model

FamilyOffice ──OWNS_ENTITY──▶ LegalEntity
     │                            │
     ├── members                  ├── jurisdictions
     ├── portfolio                └── filing obligations ──▶ forms
     ├── recommendations                               
     └── relationship actions

Jurisdiction ──▶ TaxDocument ──▶ Version ──▶ Citation
                              └──▶ Change

Components

Family Office
Advisor, profiles, portfolios, outreach pipeline, services, proposals and relationship actions.
Tax & Compliance
Entities, deterministic obligations, filing calendar, AEOI/FATCA/CRS and W-8 readiness.
Knowledge
Official forms and tax sources, immutable versions, regulatory changes, citations and provenance.
Platform
Authentication, teams, invitations, analytics, audit events, SQLite/Postgres and Neo4j.

Storage

DATA_STORAGE=sqlite selects SQLite/Postgres. DATA_STORAGE=neo4j selects local Neo4j, self-hosted Neo4j or AuraDB. SQLite stores family ownership in entities.sfo_id; Neo4j materialises OWNS_ENTITY.

Agent orchestration

LangGraph routes work to family profile, needs, services, recommendations, tax forms, tax law, regulatory changes and entity-data tools. Deterministic recommendation and filing workflows remain available without an LLM key.

Deployment and verification

docker compose up -d web
python -m pytest tests -q
python -m family.data.synth --count 24 --seed 7
python -m uvicorn web.app:app --port 5011
